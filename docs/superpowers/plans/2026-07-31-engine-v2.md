## Shared Contracts (all tasks import from here — do NOT redefine)

`services/engine/types.ts` will contain EXACTLY these shapes (Task 1 creates it):

```ts
// ---- Spans ----
export interface Span { startLine: number; startCol: number; endLine: number; endCol: number; } // 1-based lines, 0-based cols, end exclusive

// ---- Tokens ----
export type TokenKind =
  | 'WORD' | 'NUMBER' | 'OP' | 'PUNCT' | 'LPAREN' | 'RPAREN' | 'LBRACKET' | 'RBRACKET'
  | 'LBRACE' | 'RBRACE' | 'STRING' | 'MATH_QUOTE' | 'COMMENT' | 'NEWLINE';
export interface Token { kind: TokenKind; text: string; span: Span; }
// OP tokens (single token each): -> => <=> != <= >= +- -+ + - * / = < > ^ _ ' | : ; , .
// STRING: text is the INNER content (no quotes). MATH_QUOTE: inner content (no dollars).

// ---- Diagnostics ----
export interface Diagnostic { span: Span; severity: 'info' | 'warn'; message: string; hint?: string; }

// ---- Expression AST ----
export type Expr =
  | { kind: 'Num'; value: string; span: Span }
  | { kind: 'Var'; name: string; span: Span }                       // single letter
  | { kind: 'Ident'; name: string; span: Span }                     // multi-char math identifier -> \mathrm
  | { kind: 'Sym'; name: string; latex: string; span: Span }        // greek / keyword symbols (from language tables)
  | { kind: 'Text'; text: string; span: Span }                      // prose run
  | { kind: 'BinOp'; op: string; left: Expr; right: Expr; span: Span }   // + - * juxt (op: '+', '-', 'cdot', 'juxt', 'pm', 'mp', 'land', 'lor', 'cup', 'cap', 'mid', 'to')
  | { kind: 'UnaryOp'; op: string; operand: Expr; span: Span }      // 'neg' (minus), 'lnot'
  | { kind: 'Prime'; operand: Expr; count: number; span: Span }
  | { kind: 'Frac'; num: Expr; den: Expr; span: Span }
  | { kind: 'Pow'; base: Expr; exp: Expr; span: Span }
  | { kind: 'Sub'; base: Expr; sub: Expr; span: Span }
  | { kind: 'Call'; fn: string; args: Expr[]; span: Span }          // sin, sqrt, floor, choose, factorial, det, accents, overline, ray, arc...
  | { kind: 'BigOp'; op: 'sum' | 'integral' | 'lim'; from: Expr | null; to: Expr | null; span: Span }
  | { kind: 'SetLiteral'; elements: Expr[]; span: Span }
  | { kind: 'SetBuilder'; element: Expr; condition: Expr; span: Span }
  | { kind: 'Abs'; operand: Expr; span: Span }
  | { kind: 'AngleVector'; elements: Expr[]; span: Span }
  | { kind: 'Group'; operand: Expr; bracket: '(' | '['; span: Span } // explicit user parens kept for rendering
  | { kind: 'Matrix'; env: 'pmatrix' | 'bmatrix' | 'vmatrix'; rows: Expr[][]; span: Span }
  | { kind: 'Cases'; branches: { value: Expr; condition: Expr | null }[]; span: Span }
  | { kind: 'Relation'; ops: string[]; operands: Expr[]; span: Span } // n-ary chain: operands.length === ops.length + 1; ops from: = != < > <= >= in notin subset congruent similar parallel perp corresponds implies iff
  | { kind: 'Raw'; text: string; span: Span };                      // recovery: renders as \texttt

// ---- Statement segments ----
export type Segment = { kind: 'prose'; text: string; span: Span } | { kind: 'math'; expr: Expr; span: Span };

// ---- Document AST ----
export type Block =
  | { kind: 'Scope'; scopeType: string; title: string; styling: 'bold' | 'italic'; children: Block[]; span: Span }
  | { kind: 'Subtask'; depth: number; title: string; children: Block[]; span: Span }   // depth = dash count (1-4)
  | { kind: 'Claim'; statement: Segment[]; children: Block[]; span: Span }             // ?: syntax
  | { kind: 'Statement'; segments: Segment[]; span: Span }
  | { kind: 'Blank'; span: Span };
export interface DocumentAst { blocks: Block[]; macros: Record<string, string>; }

// ---- Engine API ----
export interface EngineLine { id: string; latex: string; originalLine: number; }
export interface HighlightRequest { line: number; col: number; }
export interface CompileResult {
  latexLines: EngineLine[];
  macros: Record<string, string>;
  diagnostics: Diagnostic[];
  ast: DocumentAst;
}
```

**Precedence table for the Pratt parser (Task 4) — binding powers, higher binds tighter:**

| level | constructs | notes |
|---|---|---|
| 4 | `iff` (`<=>`) | n-ary into Relation |
| 5 | `implies` (`=>`) | n-ary into Relation |
| 6 | `or`/`OR` (∨) | left-assoc BinOp 'lor' |
| 7 | `and`/`AND` (∧) | left-assoc BinOp 'land' |
| 8 | `not`/`NOT` prefix (¬) | UnaryOp 'lnot' |
| 10 | relations `= != < > <= >= in notin subset congruent similar parallel perp corresponds` | collected into ONE n-ary Relation chain |
| 12 | `->` (\to), `+-`, `-+`, `union`, `intersect`, `\mid` (`|` as divides — only inside set-builder conditions) | left-assoc |
| 20 | `+`, binary `-` | left-assoc |
| 25 | `/` | left-assoc; operands are level-30 products |
| 30 | juxtaposition, `*`, `dot` | left-assoc; juxtaposition binds TIGHTER than `/` (Laplace rule: `partial^2 u/partial x^2` = (∂²u)/(∂x²)) |
| 40 | unary minus | UnaryOp 'neg' |
| 50 | postfix `'` (prime) | on Var/Ident/Call/Group |
| 60 | `^` and `_` | right-assoc; parenthesized args `x^(...)`/`a_(...)` parse the paren content as a fresh expression |

**Angle-vector rule (exact):** at a `<` token, parse as AngleVector ONLY if (a) the `<` is in prefix position (previous token is none, an OP, `(`, `[`, `{`, or `,`), AND (b) a matching `>` exists on the same statement with no relational OP (`= != <= >= < >`), no `->`/`=>`/`<=>`, and at least one top-level `,` between them. Otherwise `<` is a comparison. (This fixes the ε-δ destruction while keeping `<1, 2, 3>`.)

**Renderer policies (Task 6) — the ONLY place output style lives:**
- Prose runs → `\text{...}`, adjacent runs merged, `\ ` between text and math segments (never after `(`/before `)`, `,`, `.`).
- Unknown multi-char math identifier (`Ident`) → `\mathrm{name}`.
- `*`/`dot`/`cdot` → `\cdot`; juxtaposition → plain adjacency with braces where needed.
- Frac → `\frac`, but if num or den transitively contains another Frac → render that tower with `\cfrac`.
- Group (user parens) → `\left(...\right)` when operand subtree contains a "tall" node (Frac, BigOp, Matrix, Cases), else plain `(...)`.
- Abs → always `\left|...\right|`.
- Relations: `<=`→`\le`, `>=`→`\ge`, `!=`→`\neq`, `in`→`\in`, `notin`→`\notin`, `subset`→`\subset`, `implies`→`\implies`, `iff`→`\iff`.
- `suchthat` → `\text{ s.t. }`. `QED` → `\blacksquare` (renderer adds NO leading `\quad` — fixes today's double-indent).
- BigOp: `\sum_{from}^{to}`, `\int_{from}^{to}`, `\lim_{from \to to}`; `\,` before a trailing differential (`dx` `dy` `dt` `du` `dv` `dz`).
- Cases → `\begin{cases}value & \text{if }condition \\ ...\end{cases}`; branch without condition and last → `& \text{otherwise}` if source word was `otherwise`.
- Scope headers: indent `\quad`×depth; sizes `\huge`(depth 0)/`\Large`(1)/`\large`(2)/`\normalsize`(3+); bold scopes `\textbf`, italic scopes (`Proof Claim Remark Example`) `\textit`; empty title renders `Type.`; spacer lines `\rule{0pt}{1.5em|1em|0.5em|0.2em}` before headers (match compiler.ts:280-307), `\rule{0pt}{0.3em}` on scope close.
- Subtask labels: depth 1 → `(i) (ii) ...`, depth ≥2 → `(a) (b) ...`; label+title rendered `\textbf{\text{(i) title:}}`; counters reset when leaving the parent scope (sibling-scoped, NOT global reset — fixes today's reset-everything bug).
- Statement indent: `\quad`×(tree depth).
- Escape hatches: STRING → Text verbatim; MATH_QUOTE → parsed math (its Idents → `\mathrm`).

**Disambiguator feature table (Task 5):** for each WORD token not already forced (see absolutes), compute score = Σ weights; score > 0 → math, score ≤ 0 → prose.

| feature | weight |
|---|---|
| ABSOLUTES (skip scoring): inside STRING → prose; inside MATH_QUOTE / set-builder / function args / matrix / cases / sub / sup → math; function-name WORD immediately followed by `(` → math; scope keyword at line start → handled by document parser | — |
| single alphabetic char | +3 |
| word in `mathKeywords`/`symbolMap`/greek tables (bare) | +4 |
| word in stop-word lexicon (articles, aux verbs, prepositions, proof verbs, math adjectives — port `textStopWords` + `proseIndicators*` from compiler.ts:73-96,171-180) | −5 |
| unknown multi-char word | −3 |
| nearest non-punct neighbor (each side): is prose-classified word or stopword | −2 per side |
| nearest neighbor (each side): single letter, NUMBER, or math OP (`= + - * / ^ _ < > !=` …) | +2 per side |
| comma immediately before (`", and"`) | −3 |
| statement contains quantifier/logic token (`forall exists suchthat => <=> in notin subset`) AND both neighbors are single letters | +3 |
| word is `a`/`A` followed by a multi-char non-keyword word | −4 (article) |

Ties/defaults reproduce today's behavior: single char → math, multi-char unknown → prose. Every decision records `{word, span, verdict, score, reasons: string[]}` retrievable via `explainSegmentation(statement)`.

### Task 2: Lexer (`lexer.ts`)

**Files:**
- Create: `services/engine/lexer.ts`
- Test: `tests/engine/test-lexer.mjs`

API: `export function lex(source: string): { tokens: Token[]; diagnostics: Diagnostic[] }` — tokens include NEWLINE per line break; COMMENT swallows `//…` to EOL.

Rules (implement exactly):
1. Unicode normalize first: `∣│∥`→`|`, `·•∙`→` dot `, `≤`→`<=`, `≥`→`>=`, `≠`→`!=`, `→`→`->` (track column mapping is NOT required — normalization may shift cols only on these rare chars; keep spans against the NORMALIZED text and store the normalized source on the result for downstream span users).
2. Multi-char OPs tokenized greedily in this order: `<=>` `=>` `->` `!=` `<=` `>=` `+-` `-+` then singles ``= < > + - * / ^ _ ' | : ; , . ( ) [ ] { }``.
3. `"..."` → STRING (inner text; unterminated → diagnostic warn "unterminated quote — treated as text" and STRING to EOL). `$...$` → MATH_QUOTE (same recovery).
4. WORD = `[A-Za-z][A-Za-z0-9]*` (NO underscore — `_` is an OP so `a_i` lexes WORD OP WORD). NUMBER = `\d+(\.\d+)?`.
5. `Math.xxx` lexes as WORD(`Math`) OP(`.`) WORD — the parser joins via MATH_PACKAGE lookup.

### (b) Goal 7 ("single source of truth") — decide the final scope

The design spec's goal 7 asked for `language.ts` to be the single source of
truth "consumed by the engine, editor highlighting, autocomplete, and the
syntax-help dialog." Two of those four hold today: the engine
(`services/engine/`) and editor highlighting (`Editor.tsx` imports
`language.ts` directly). The other two do not: `constants.ts`'s
`AUTOCOMPLETE_DATA` and `services/syntaxReference.ts` are hand-curated,
separate data — now documented as such in syntaxReference.ts's header
(post the 2026-08-05 honesty pass), rather than claiming a sync that never
existed.

What exists instead, as of that same pass, is a compat GATE rather than a
unification: `tests/engine/test-autocomplete-compat.mjs` compiles every
`AUTOCOMPLETE_DATA` template through the real engine and fails on any 'warn'
diagnostic, so autocomplete-vs-engine drift is caught in CI instead of by a
user hitting a broken suggestion. `syntaxReference.ts` has no equivalent gate
— it doesn't feed `compile()`, so there is nothing to compile-and-compare; its
`output:` strings are just literal values checked by a reader's eyes (and,
now, cross-checked by hand against `docs/mathscript-spec.md` when edited).

Two ways to close this out, not decided here:
1. **Unify** — generate `AUTOCOMPLETE_DATA`'s templates and
   `syntaxReference.ts`'s syntax/output/description entries FROM
   `language.ts` (`FUNCTIONS`, `SCOPES`, `SYMBOL_MAP`, ...), as goal 7
   originally asked. Real work, not a mechanical extraction: the two
   consumers want different SHAPES of the same data (autocomplete wants
   insertable templates with `$0`/cursor-offset metadata; syntaxReference
   wants display syntax/output/description triples grouped into UI
   categories).
2. **Accept curated-with-compat-gate status** — keep both hand-curated, and
   treat (a)'s AUTOCOMPLETE_DATA gate (exists today) plus a hypothetical
   future syntaxReference-vs-`docs/mathscript-spec.md` gate (does not exist
   yet) as the permanent guardrails instead of a data-model unification.

The gate in (2) already closes the SILENT-drift failure mode goal 7 was
really guarding against, which makes option 2 a legitimate stopping point
and not just a deferral — but it is a product/architecture call for someone
to make on purpose, not the default by omission.

### (c) Open known limitations

Carried over unchanged by this follow-up pass — full detail in
`docs/superpowers/specs/2026-08-04-golden-migration-notes.md`'s "Known
limitations" section:

- **`fdot g`** (the half-glued dot-product spelling) is not recognized; only
  `fdotg` (fully glued) and `f dot g` (fully spaced) resolve to `f\cdot g`.
- **Multi-char identifiers glue to their neighbours with no spacing** outside
  a set-builder condition (`x divides y` → `x\mathrm{divides}y`). This is the
  limitation the syntaxReference.ts "divides" fix in this same pass routes
  around, by documenting the supported `|` spelling (`a | b` → `a \mid b`)
  instead of the bare word.
- **Geometry keywords** (`triangle`/`angle`/`parallel`/`degree`/`congruent`,
  and relation-word siblings `similar`/`perp`/`corresponds`) **always win
  over prose**, with no diagnostic, because scoring them contextually (the
  fix already applied to `partial`) needs multi-letter point-label operand
  support first — see the next item.
- **Multi-letter geometry point labels aren't recognized as a unit** outside
  the accent functions (`overline`/`ray`/`arc`): a bare multi-letter name
  next to a relation word like `parallel`/`congruent` falls back to ordinary
  per-word scoring, which can read the identical shape of word as math or
  prose depending only on which side of the sentence it sits.
